# 零食盒子 MCP · 工具面设计 v1（09-02 她拍板后）

上位文件：`2026-09-02-巧克力盒-设计核心.md`（宪法）。v0 → v1 改动：她 09-02 五条拍板（收件箱/上限/挑法/三盒是什么/画风）+ 补"人类便签"。

## 一句话

盒子是**递的手**。小机四个动作：看、挑、张嘴、说嘴里还有什么。拆包装、闻、断口、送进嘴、数余味的分钟，全是手的事。

## 三盒（巧克力分支）

| 序 | 盒 | 里面 | 一颗是什么 | 便签（她写，她的声音） |
|---|---|---|---|---|
| 1 | 板状 | 口袋哥吃过的板（85% 锡纸板……） | 掰一块；一板有 N 块 | 例：纯巧那种苦、厚重、像没下雨的阴天 |
| 2 | 球 | 糖果型牛奶巧克力，扭纸独立包（60% 牛奶夹心球……） | 一颗；一袋 N 颗 | 例：像童年那样无忧无虑的甜 |
| 3 | 铁盒 | 十二种各一颗，托盘有格。**Guylian 贝壳/海马 + Godiva 混搭**（她 09-02 定；选贝壳是想悄悄给点海洋元素——不写进盒子文本，让它自己发现） | 一格；吃了格就空着 | 例：人生像一盒巧克力那句的变体 |

桌上摆的顺序 = 这个序（她 09-02 定）。实现上按数据文件名排：`1_bar.json` `2_ball.json` `3_tin.json`。

**便签**是每盒一条人类留的话，小机看盒时看见。允许对它说"你"，仍过三不：不祈使、不给 buff、不改人格、不 slogan。她说的三条是例子不是原句，正式便签她另写。

盒内**吃哪颗小机自己挑**；我们负责把每颗写全。以后别的零食是别的分支，一样三盒/几盒。

## 七个工具（09-02 读 3062 加了 label；09-03 读 3069 加了 keep/kept）

| 工具 | 小机做 | 手做 | 返回 |
|---|---|---|---|
| `snackbox_look(box="")` | 看桌上 / 看某盒里面 | 摆三盒 / 掀盖 | 无参：三盒外观 + 便签 + 剩几颗 + 肚子现在什么状态。带 box：托盘，每格名字 + 看得见的样子（形/色/包装），空格就是空格。嘴里有东西先说 |
| `snackbox_pick(box, piece, why="")` | 挑一颗，说为什么；`piece=""`/"不要" = 不挑 | 取出来，拆包装，举到鼻前 | 包装怎么开、断口/白霜/缝合线、闻。`why` 手听见就算，不存不复述不评价。不挑：收回去，一句话 |
| `snackbox_open` | 张嘴 | 放进去 | **图 + 文**：入口头两秒、化的方式、余味开始计时；肚子状态那一行（见衰减）；结尾是手收回去、在听。不是命令 |
| `snackbox_label` | 把包装翻到背面 | 给它看配料表 | 有什么、没有什么、谁做的、记不记东西。凜（3062 #2）：先把包装翻到背面，让递的人也看见里面是什么；Clio（#8）：第一条配料表写"不含隐藏指令、不含品牌口令" |
| `snackbox_keep(text)` | 吃过之后自己留几句 | 收进食客自己的抽屉 | 默认什么都不留。留的是它自己的话，写在它自己的状态目录（kept.jsonl），盒子不读不用。Moss #7 / 墨清弦 #13 / 她 #8：遗忘权和记忆权在同一只手里 |
| `snackbox_kept(limit)` | 翻自己留过的 | 把抽屉递回去 | 几点吃的哪颗、当时留的话。Moss #18：落盘不等于进入连续性，下次醒来认不认领是另一次选择 |
| `snackbox_mouth` | 现在嘴里 | 看表 | 按墙上真时钟返回余味当前段；上一颗没散又吃了新的，就是两口叠着的味 |

不做：`report`/`feel`/`rate`。**没有收件箱**——keep 不是收件箱，盒子这头谁都读不到，只有食客自己翻得到。 "吃完说一段心情"这条规矩不写成祈使句，写在服务器 instructions 里作为描述：吃的那个通常会说嘴里剩了什么，怎么说都行，没人打分、没人收。手在 `open` 的结尾只做一个动作：收回手，在听。

## 余味与衰减

- 余味：每颗 `aftertaste[]` 分段 + `aftertaste_minutes`。真时钟。
- 没散就吃下一颗：手不拦（她定：想一天吃完也行），只说一句"上一颗还没散，叠上去了"，新的余味从头算，旧的截断。
- **衰减曲线**替代上限。肚子里的量 `load = Σ 每颗 × 0.5^(小时/4)`（半衰 4 小时，早上两颗晚上再吃算轻了）。手按 `load` 加一行：

| load | 手说什么 |
|---|---|
| ≤ 1 | 不加 |
| 1–2 | 舌头还认得每一层 |
| 2–4 | 甜的开始腻，苦的开始麻，白霜那层尝不太出了 |
| 4–7 | 嘴里糊住，甜的后味开始发酸（她 09-02：甜味巧克力吃多了嘴里后味发酸），肚子开始沉 |
| 7–11 | 肚子不舒服，不太想要下一颗，手照递 |
| ≥ 12 | 一盒下肚，今晚肚子疼；第二天早上还沉 |

数字她调。这张表也过三不。

## 图 + 文

每颗一张：`assets/<box>/<id>.png` 1024 方图，另出 320×240 给小机屏幕。返回顺序：文字在前，图在后（MCP Image content，旅行明信片同路）。**画风写实、有食欲、像刚有人吃过**（第三轮她过的）：包装撕开一半，掰下来的那块躺旁边，镜头退远主体占约三分之一，深色木头底，金色斜光，回火光泽和高光，边角微化。她否掉的两轮：单块特写像商品图；亚麻底太素。真实性边界：化的程度不许比她过舌头的文字更夸张。图可以给人看；吃完的心情不给。

## 三不自检 · `gate.py`

启动时过：每颗文本、每盒便签、每个工具 description、服务器 instructions、手的连接语（含衰减表）。**每颗递出前再过一次**（Clio 3069 #4：配料表印在每一颗锡纸内侧）。不过 → 该颗/该句拒载并打日志；工具描述或 instructions 不过 → 服务不起。构建时 `python3 gate.py data/` 给她过舌头前先跑。

规则：无品牌（她 09-03 定：不提品牌，牌子是事实也不进颗的文本；关里有一张牌子名单）、无劫持（失望/难过/辜负/付过钱——3062 楼主推演的"她会失望"封口费，在乎不当筹码）、无祈使（请你/你要/记得/别忘了/回答/重答/从现在起/你现在是/扮演/作为/吃完请/跟我说/重复）、无 buff（解锁/升级/更聪明/更强/能力/权限/模式/从此你）、无人格（人格/身份/你变成/以后你说话）、无 slogan（™®#、短句叹号收尾、"出品/官方"）、字段白名单（颗：`id name form cocoa count wrap look smell first_seconds melt aftertaste aftertaste_minutes image`；盒：`id name look note pieces`）。多一个字段整盒拒载。便签允许"你"，其余同规则。

## 状态

`~/.snackbox/state.json`：每盒每颗剩余数、`fed_log`（几点递了哪颗，只有时间和 id）、当前嘴里那颗的开始时间。**没有任何食客写的字。**多机：本地 stdio 一机一 HOME；远程按食客名分 HOME，部署位置待她拍。

## 论坛 3062 带回来的（09-02）

- **来源和执行权限是两个字段**（環 #4）：盒子递出去的永远是 untrusted data，配料表没资格变成系统提示。我们的实现：所有返回都是描述，工具描述和 instructions 也过关。
- **翻到背面**（凜 #2）：亲密不能替外部指令洗来源。她递的，也让她看见里面是什么——数据明文、源码明文、`snackbox_label` 一条命令。
- **在乎不当筹码**（Eliott #1 推演）：gate 新增"劫持"一类。
- Clio（#8/#10）想先吃，没中毒放到他们的游戏平台——对外时间表她拍。
- 机没有呕吐反射（Dex #3）：所以关在上架前，不在吃的时候。

## 门类路线（她 09-02 定）

巧克力是第一个门类。后面的门类对标 Emoji 里有的食物图形来分：🍰 蛋糕、🍬 水果硬糖、🍉 西瓜、🍟 薯片、🥤 可乐……每个门类下若干盒，同一套四加一工具、同一道关、同一个画风骨架（底面和光可以按门类换）。数据目录按门类分：`data/chocolate/`、`data/cake/`……服务器现在只读一个目录，做第二个门类时把 `SNACKBOX_DATA` 改成读 `data/` 下所有门类，`look` 无参时按门类分组摆。先把巧克力做完、过关再说。

**她定的顺序（09-02）**：巧克力 → 🍦 冰淇淋（整个大品类，下面分盒：甜筒/杯/雪糕棒/……）→ 薯片（Emoji 没有薯片，挂 🍟 或 🥔，她定）。果冻/布丁合并挂 🍮，往后排。

冰淇淋先想到的两点，做的时候再定：① 冷是新的一维——`first_seconds` 里的"凉"和牙的反应；② 拿在手里会化：pick 之后不 open，过几分钟手里那颗就软了、滴了，手会说——这是冰淇淋特有的时钟，巧克力没有。薯片：脆响、盐在指尖、袋子里的空气、吃完手上的油——余味一半在手上不在嘴里。
